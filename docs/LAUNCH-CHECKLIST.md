# Kinra public launch checklist

Prepared 20 October 2026. Planning baseline: `D:/Projects/kinra-v2`, source `344eca5206bb6bd0f08e6cfed1d4e999f9917e19`. This checklist authorizes no implementation, production changes, outreach or launch.

**Launch verdict: readiness and final launch signoff are not yet recorded in this checklist.** Kinra has a substantial implemented and tested product, with a dated READY deployment at `kinra.fit`. Public launch acceptance is still open in this record; existing deployment authorization remains unchanged. No row below is marked PASS: historical tests establish useful coverage, but do not establish all the operational, device, privacy, content and business gates needed for launch.

## How to use this list

- **P0 — hard gate:** must PASS before inviting a launch cohort that uses real personal data. Identity, privacy, data integrity, recovery and support always apply. Feature-specific P0 rows apply when that feature/role is exposed; exclusion requires disabling access and removing promises, with evidence. An exposed unsafe feature cannot be waived by adding a disclaimer.
- **P1 — scope gate:** must PASS for every feature, audience, language and platform included in the launch promise. A feature may instead be explicitly DEFERRED, hidden/disabled and removed from launch claims, with the product owner's recorded decision. Core safety, identity and data-integrity requirements remain P0.
- **P2 — later:** optional backlog; does not block v1 unless promised, then becomes P1.
- **Implementation:** `IMPLEMENTED` means documented in current V2 evidence; `PARTIAL` means only the stated part exists; `MISSING` means the cited current evidence explicitly identifies a gap; `UNVERIFIED` means this review found no adequate implementation proof; `DECISION NEEDED` means a product/operating choice is required. Absence of proof is not proof of absence.
- **Acceptance:** `OPEN` = work/evidence needed; `PASS` = acceptance met on a named candidate; `FAIL` = reproduced unmet criterion; `BLOCKED` = named dependency prevents checking; `DEFERRED` = approved exclusion with reason and removal of user-facing promises. Keep implementation state separate from acceptance.
- Owners below are **suggested roles, not assigned people**. Product = Amrudin/product owner; Eng = engineering; QA = release tester; Sec = security reviewer; Ops = service operator; Content = qualified content reviewer; Privacy = responsible privacy/legal reviewer; Support = support/moderation operator. Product must assign real names before signoff.
- For every PASS attach: ID, exact commit/deployment/schema, environment, date, tester, role/locale/device/browser, fixture or scenario, expected/actual outcome, and sanitized evidence path. Record defects and retests. Never put credentials, one-time links or private user records in this file or the vault.
- Test with owned synthetic identities and fictional records. Destructive restore, erasure, failure injection and migration tests belong in an isolated representative environment; production smoke must be explicitly scoped and fixtures cleaned. This document does not execute those tests.

## Critical path

- [ ] **1. Agree the launch contract:** cohort, countries, age range, roles, languages, device support, exposed modules and honest claims (L01–L05). EN/BS/DE built-in UI and original program metadata are required; custom text remains authored text.
- [ ] **2. Close the trust gates:** actor/role/file access and actual coach audience, account lifecycle, privacy/support routes and content safety (S01–S08, A01–A05, C01–C05, O01–O03).
- [ ] **3. Prove the core journey on real devices:** signup → first useful action → save → reload → correct/edit → export/erase, including EN/BS/DE, interruption and denied permissions (F01–F05, W01–W05, P01–P04, N01–N04, H01–H04, U01–U06).
- [ ] **4. Prove recoverability and operation:** isolated restore, compatible migrations/rollback, alert routing and incident ownership (R01–R07).
- [ ] **5. Run a limited, supported pilot, fix blocking findings, then sign the exact candidate:** O04–O07. An accessible deployment or passing test count is not this signoff.
